# 成蹊云 CRM（本地演示切片）

> **仅限虚构数据演示。不得输入真实姓名、手机号、身份证号、支付信息或任何真实个人资料。**

这是一个可运行的本地 SQLite 业务切片，用来演示客户去重、权限范围、订单资金台账、AI 风险转人工、客服工作台，以及招生报名、审核、学员建档和跟进任务工作流。它不是生产 CRM，也不是最终的云端部署。

## 前提与启动

需要 Node.js 24 或更高版本（内置 `node:sqlite`）。在仓库根目录执行：

```bash
npm run crm:start
```

默认打开 [http://127.0.0.1:4310](http://127.0.0.1:4310)。控制台出现 `CRM_READY ...` 表示迁移和虚构 seed 已完成，工作台可以使用。

运行测试：

```bash
npm run crm:test
```

也可用 `pnpm crm:start` 和 `pnpm crm:test`。

## 本地演示身份

工作台可选的固定虚构身份全部由服务端决定，浏览器无法提交角色或数据范围：

- `admin-1`（管理员）：查看本演示切片中的全部虚构客户、会话和订单。
- `service-1`（客服）：仅查看 `campus-a` 中负责人为 `service-1` 的客户及其会话。
- `finance-1`（财务）：只读查看本校区客户、订单和必要手机号；不能查看会话，也没有写入权限。

本切片的财务身份是只读的。付款、退款等资金写权限需要后续单独完成授权与审批决策，不能把当前演示当作可收款或可退款系统。

## 招生报名、审核与跟进

这是一条本地演示工作流，所有角色、权限范围和生命周期字段均由服务端判定；浏览器选择的演示身份不会变成客户端可自定义的授权。

- `consultant-1`（招生顾问）只能为自己负责、且位于 `campus-a` 的客户提交报名，并可查看自己范围内的报名和跟进任务。
- `supervisor-1`（主管）只能在 `campus-a` 的 `team-a` 范围内审核报名、查看学员并管理跟进任务；不能跨团队作决定。
- `admin-1`（管理员）可在本演示切片的全部虚构范围内审核报名、查看学员并管理跟进任务。

工作流使用以下五个固定 API 路径；请求中未列出的字段会被忽略或被服务端生成，不能借此改变权限、归属或生命周期。

- `/api/enrollments`：`GET` 读取；`POST` 只接受 `requestId`、`customerId` 和报名资料 `currentEducation`、`targetLevel`、`school`、`major`、`classType`。服务端生成报名编号、`pending` 状态、提交人和提交时间。
- `/api/enrollment-decisions`：`POST` 只接受 `requestId`、`enrollmentId` 和决定 `status`/`reason`。服务端校验审核权限，并写入决定人、决定时间和最终状态。
- `/api/students`：仅 `GET`。学员档案不接受浏览器创建；仅在报名通过时由服务端建立并关联报名。
- `/api/follow-up-tasks`：`GET` 读取；`POST` 只接受 `requestId`、`customerId` 和 `title`/`dueAt`。服务端将任务归属为客户负责人，生成编号和 `open` 状态。
- `/api/follow-up-task-status`：仅 `POST`，只接受 `requestId`、`taskId` 和目标 `status`；服务端按任务授权与状态机更新，不能修改任务归属、来源或到期时间。

报名提交后固定为 `pending`。主管在其团队范围内、或管理员在全局范围内，只能将待审核报名决定一次为 `approved` 或 `rejected`（驳回必须给出原因）。通过时，服务端原子创建一份 `active` 学员档案和一条“完成报名交接”的 `open` 跟进任务，任务归属客户负责人，到期时间严格为批准时刻加 24 小时。

手工或审核生成的跟进任务状态只能前进：`open` 可变为 `in_progress`、`completed` 或 `cancelled`；`in_progress` 只能变为 `completed` 或 `cancelled`；`completed` 与 `cancelled` 是终态。已有待审核报名或学员档案的客户不能重复报名。

> **范围警告：仅限虚构数据。** 此工作流不提供材料上传、生产身份认证、任意指派任务或客户、通知功能，或重复报名能力。不得将其用于真实招生、真实个人资料或生产审批。

## 数据与配置

默认数据库在本机用户目录的 `~/.chengqiyun-crm-data/chengqiyun-crm.sqlite`，不在仓库内。首次启动会安全创建缺失目录；程序绝不会清空或删除已有目录。

可按需覆盖：

```bash
CRM_HOST=127.0.0.1 CRM_PORT=4311 CRM_DATA_DIR=/safe/local/crm-demo npm run crm:start
```

端口必须是 1–65535 的整数；主机不能为空且不得包含控制字符；数据路径必须是目录。在 POSIX/Unix 环境，按 `Ctrl+C` 或发送 `SIGTERM` 会先停止 HTTP 服务，再关闭 SQLite，一次且仅一次。Windows 本地控制台请使用 `Ctrl+C`；仅在 Node IPC 通道存在时，父进程可发送固定的 `{ type: 'crm:shutdown' }` 控制消息，供测试或托管父进程使用，HTTP 不提供该能力。

首次启动会用真实业务服务写入三名固定虚构学员及虚构合同、已确认/待处理资金流水和一条人工接管会话。所有写入均使用固定幂等请求号，重复启动或中断后的再次启动不会重复生成数据。

## 当前范围与限制

已实现：本地客户去重、服务端角色与范围控制、脱敏、追加式订单台账、审计、风险转人工、聚合仪表盘和同源工作台。

尚未实现：云端/ PostgreSQL 部署、生产身份认证、真实 FastGPT 接入、真实企业微信或微信连接器、文件材料上传和完整审批流。请不要把本地演示身份或 SQLite 文件用于生产。
