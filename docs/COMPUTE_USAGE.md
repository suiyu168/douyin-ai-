# 算力使用与复盘口径

## 目标

把高能力推理优先用于架构、代码、疑难排错和安全审查，减少上下文恢复、重复测试、无效并行和冗长日志造成的消耗。

## 每三天报告内容

1. 账号官方数据：5 小时窗口和 7 天窗口的已用比例、重置时间。
2. 项目估算：最近 72 小时本地会话 token，按当时工作目录归入项目。
3. 工作位置：按 Git 提交、变更文件和工具工作目录，汇总到功能或模块。
4. 浪费检查：重复上下文、重复全量测试、无产出子 Agent、过长输出、重复搜索和失败重试。
5. 下一周期措施：最多三项，可以实际执行并可在下一次复盘核对。

## 数据边界

- 账号窗口比例来自 Codex 官方用量接口。
- Codex 暂不提供精确的“项目账单”；项目、模块和 token 分布是本机日志的遥测估算。
- 不读取完整聊天正文，不收集业务数据，不把虚假精度写进报告。
- 如果本地日志缺失、跨设备工作或会话跨越统计边界，报告必须说明覆盖范围和误差来源。
