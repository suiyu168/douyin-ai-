# 知程云知识库与客服答疑工作台设计

日期：2026-09-10

## 1. 目标与范围

本里程碑在现有本地 CRM 切片中补齐“资料管理 → 审核发布 → 服务端检索 → AI 分流 → 客服处理”的可运行闭环。它验证业务规则和接口边界，不接入真实 FastGPT、企业微信、个人微信或生产身份系统。

本期包含：

- 政策、产品、话术、风险禁答、优秀会话五类知识资料。
- 资料创建、修订、提交审核、审核通过/拒绝、发布和失效。
- 不可覆盖的版本历史与安全审计摘要。
- 服务端仅从当前有效版本中检索引用，并将引用交给现有 AI 分流规则。
- 知识库管理页和客服会话处理页。

本期不包含：文档上传与切片、向量数据库、真实大模型生成、FastGPT 部署、渠道消息发送、知识运营质量报表和真实业务资料。

## 2. 架构与可信边界

知识库以独立领域模块实现，CRM 服务负责权限、事务、幂等、审计和 DTO，HTTP 层只接收白名单字段。检索器通过小型接口向会话分流提供已验证的知识版本；未来 FastGPT 适配器必须实现同一接口，不能绕过 CRM 的发布状态和有效期校验。

浏览器只能提交客户消息，不能提交模型置信度、引用、知识状态、审核人或发布时间。当前没有真实模型时，服务端使用确定性的本地检索结果：命中当前有效知识则形成引用并进入“待人工确认”；风险问题始终“人工接管”。只有后续受信任模型适配器提供合格置信度时，系统才允许“AI 已回复”。这样不会把关键词命中伪装成真实 AI 回答。

## 3. 数据模型与状态机

### 3.1 知识条目

知识条目保存稳定 ID、分类、标题、创建人和创建时间。分类固定为：

- `policy`：政策库
- `product`：产品库
- `script`：话术库
- `risk`：风险禁答库
- `excellent_conversation`：优秀会话库

### 3.2 知识版本

每次修改都新增版本，不覆盖旧版本。版本保存正文、来源说明、适用关键词、生效时间、失效时间、版本号、状态及提交/审核/发布元数据。

状态流固定为：

`draft → pending_review → approved → published → expired`

审核拒绝为 `pending_review → rejected`；被拒版本只能复制为新草稿后重新提交。一个条目同一时刻最多存在一个已发布且有效的版本。发布新版本时，旧的已发布版本自动失效。删除只允许删除从未提交的草稿；其他版本通过失效保留历史。

有效引用必须同时满足：状态为 `published`、审核结果为通过、已到生效时间、未到失效时间。沿用现有“到达失效时间即无效”的半开区间规则。

## 4. 权限

| 动作 | 管理员 | 主管 | 客服/咨询师 | 其他角色 |
|---|---|---|---|---|
| 查看已发布知识 | 全部 | 全部 | 全部 | 否 |
| 查看草稿和审核历史 | 全部 | 全部 | 否 | 否 |
| 创建、修订、提交审核 | 可以 | 可以 | 否 | 否 |
| 审核通过或拒绝 | 可以 | 可以，但不能审核本人提交 | 否 | 否 |
| 发布、失效 | 可以 | 否 | 否 | 否 |
| 查看本人范围内会话 | 可以 | 所属团队 | 本人客户 | 否 |
| 确认建议、人工接管 | 可以 | 所属团队 | 本人客户 | 否 |

审核和发布必须由服务端当前 actor 决定。主管审核采用双人原则，不能审核自己提交的版本；管理员保留演示环境的最终发布权限。

## 5. 领域与服务接口

知识领域模块负责输入规范化、分类与状态转换、有效期判断、版本摘要和确定性关键词检索。CRM 服务新增：

- `createKnowledgeEntry`
- `reviseKnowledgeEntry`
- `submitKnowledgeVersion`
- `reviewKnowledgeVersion`
- `publishKnowledgeVersion`
- `expireKnowledgeVersion`
- `deleteKnowledgeDraft`
- `listKnowledgeEntries`
- `searchPublishedKnowledge`
- `listConversations`
- `updateConversationStatus`

所有写操作复用现有事务、`requestId` 幂等、actor 签名和审计机制。审计只记录条目 ID、版本号、状态变化、分类和安全字段名，不记录正文、客户消息或优秀会话原文。

知识列表 DTO 根据权限裁剪：普通客服只得到当前有效版本的标题、分类、正文、来源和有效期；管理员/主管可以看到版本状态和流程元数据。任何 DTO 都不返回内部关键词评分或完整审计载荷。

## 6. 会话处理流程

1. 客服在其可见客户下提交一条虚构咨询消息。
2. 服务端先运行强制人工风险规则。
3. 非风险消息只检索当前有效知识，返回固定上限、确定顺序的引用。
4. 没有可靠引用时进入 `suggestion`，原因是 `NO_VALID_CITATION`；本地无模型置信度时，即使命中也保持 `suggestion`。
5. 风险消息进入 `human_required`，知识引用不能覆盖风险决定。
6. 客服可将 `suggestion` 标记为已确认，或接管 `human_required`；每次状态变化写入审计。

会话处理状态与 AI 决策分开保存：AI 决策仍为 `auto_reply`、`suggestion`、`human_required`；人工队列状态为 `pending`、`confirmed`、`taken_over`、`closed`。这样人工动作不会篡改原始 AI 判断。

## 7. HTTP API 与错误处理

新增资源接口用于知识列表、创建/修订、提交审核、审核、发布、失效、知识检索、会话列表和会话状态更新。列表查询只接受固定筛选项；写接口只接受业务字段，忽略并拒绝越权流程字段。

错误继续使用 `{ error: { code, message } }`，新增稳定错误码：非法分类/状态转换、重复有效版本、无权审核本人内容、知识版本不存在、会话状态转换非法。未知字段、超长正文、空关键词、无效日期、失效早于生效和重复请求载荷冲突均失败且不产生部分写入。

正文长度上限为 20,000 字符，标题 200 字符，关键词最多 30 个且每个最多 80 字符；检索最多返回 5 条，先按命中关键词数量，再按版本发布时间和稳定 ID 排序。

## 8. 工作台

现有“知识库模块建设中”导航改为可用页面，包含分类/状态筛选、知识列表、版本状态、有效期和创建入口。管理员与主管看到编辑和流程按钮，普通客服只看到已发布资料。

AI 会话页升级为队列，展示客户安全摘要、原消息、AI 决策、风险原因、知识引用和人工处理状态。界面不提供置信度或引用编辑入口；失败时显示固定错误信息并允许重试，空状态显示操作指引。

保持现有深色视觉语言、同源 API、键盘可达性和移动宽度下的可读布局。不引入新的前端框架。

## 9. 测试与验收

采用测试先行，分层验证：

- 领域测试：分类、状态机、版本不可覆盖、有效期边界、关键词规范化和稳定检索排序。
- 权限测试：角色读写范围、主管不能自审、浏览器伪造审核/引用/置信度无效。
- 服务测试：事务回滚、幂等重放与冲突、发布替换旧版本、审计摘要不泄露正文。
- HTTP 测试：接口方法、字段白名单、错误结构、查询筛选和请求大小限制。
- 工作台测试：知识创建审核发布、有效知识进入引用、风险强制转人工、人工状态处理。
- 回归测试：现有客户、报名学员、任务、订单资金、仪表盘与旧应用测试继续通过。

验收闭环：管理员创建并发布一条虚构政策；客服提交相关普通问题后看到引用和待确认状态；提交退款或保过问题后无条件进入人工接管；知识失效后不再被新会话引用；全过程存在不含正文与客户消息的审计记录。

## 10. 演进边界

后续 FastGPT 适配器只负责检索/生成和返回候选引用、置信度，不拥有知识发布权。CRM 服务再次校验候选引用是否当前有效，并由现有风险规则决定是否允许自动回复。适配器故障时系统退化为人工处理，客服仍可浏览已发布资料和记录人工结果。
