# 成蹊云 CRM：第一阶段开发计划

> 暂定产品名：**成蹊云**  
> 代码仓库名：`adult-education-crm`  
> 目标：用可验收的垂直业务闭环，把现有本地抖音工具逐步替换为云端成人学历提升招生 CRM。

## 1. 已确认范围

第一阶段必须形成以下闭环：

1. 微信、表单或 Excel/CSV 导入客户。
2. 自动去重并保留每一个来源记录。
3. 客服基于受控知识库答疑；高风险或低置信度问题转人工。
4. 咨询师建立学历评估、方案、报名档案与订单。
5. 财务逐笔确认收款，系统计算应收、实收、待收与退款后净回款。
6. 成交客户转为学员，继续管理材料、入学、学籍和服务记录。
7. 管理者查看漏斗、人员业绩和回款报表。

第一阶段明确不做：会计总账、税务申报、绕过微信限制的个人号无人值守自动发送、未经人工确认的退款或非标准优惠。

## 2. 技术路线

采用“模块化云端单体 + 独立 AI 中台”，先把业务边界做清楚，达到规模后再拆微服务。

```text
浏览器管理端 / 后续桌面壳
          │ HTTPS
          ▼
成蹊云 API（统一鉴权、业务规则、审计）
  ├─ 客户与会话
  ├─ 报名与学员
  ├─ 订单与财务台账
  ├─ 任务、权限与报表
  └─ 渠道/AI 适配层
          │
          ├─ PostgreSQL（唯一业务数据源）
          ├─ Redis + 任务队列（异步任务、重试、限流）
          ├─ S3 兼容对象存储（合同、凭证、材料）
          └─ FastGPT（独立知识库与工作流）
```

建议技术栈：

- Web：React + TypeScript，采用成熟组件库建立管理后台。
- API：Node.js + TypeScript 的模块化服务，提供 OpenAPI 文档。
- 数据库：PostgreSQL；金额使用最小货币单位整数，不使用浮点数。
- 队列：Redis 支撑消息处理、AI 调用、导入和报表任务。
- 文件：兼容 S3 的私有对象存储，浏览器只获得短时授权地址。
- 部署：Docker Compose 用于开发和单机验收，生产使用托管数据库或规范化容器部署。
- AI：FastGPT 独立部署，CRM 只保存知识条目版本、引用、置信度和业务决策记录。

现有 `app/`、`scripts/` 和 `test/` 作为旧系统基线保留；新系统放入独立目录，完成迁移验收前不删除旧代码。

## 4. 核心数据规则

### 4.1 客户去重

- 手机号标准化后精确匹配；原号码和标准号码分别保存。
- 微信号标准化后精确匹配，不使用昵称做自动合并。
- 身份证只在明确授权的导入流程中使用；去重保存不可逆摘要，原文加密保存且按权限展示。
- 只有一项弱证据时进入“疑似重复”队列，不自动合并。
- 合并客户必须记录主记录、被合并记录、字段取舍、操作者和时间，并支持审计追踪。

### 4.2 订单与收款

- 订单成交价 = 标价 - 已批准优惠 + 已批准调整。
- 应收以订单和调整记录计算，不能通过备注覆盖。
- 收款只追加，不修改已确认记录；纠错通过冲正记录完成。
- 退款是独立记录，审批通过后计入净回款。
- 所有金额使用整数分；币种第一阶段固定为人民币，但数据库保留币种字段。

### 4.3 权限

- 每一次查询同时校验“角色权限”和“数据范围”。
- 客服默认仅看本人客户；主管看所属团队；财务看订单与必要身份字段；管理员看全局配置与审计。
- 身份证、手机号、合同、支付凭证分别控制查看与导出权限。
- 停用员工立即失去登录资格，历史记录不删除，未完成业务必须转交。

### 4.4 AI 自动回复

- 仅引用“已审核、已生效、未过期”的知识版本。
- 投诉、退款、合同、付款异常、资格不确定、非标准价格、敏感资料和承诺类问题强制转人工。
- 没有可靠引用或置信度不足时只生成建议，不自动发送。
- 每次决策保留输入消息、知识引用、模型版本、置信度、风险命中和最终处理人。
- AI 或 FastGPT 不可用时，会话继续进入人工队列，不能阻断客服工作台。

## 5. 迭代顺序与验收

### 里程碑 0：工程基线

- 建立私有 GitHub 仓库并保存旧系统基线。
- 引入格式化、静态检查、单元测试和持续集成。
- 提供开发环境示例配置，不提交任何真实密钥或客户资料。
- 本地一条命令启动数据库、缓存、对象存储、API 和 Web。

验收：新电脑按 README 可以启动；自动检查全部通过；仓库无真实凭据和运行数据。

### 里程碑 1：组织、账号与审计

- 建立校区、团队、员工、角色、权限和数据范围。
- 支持登录、退出、会话失效、密码策略、员工停用和业务转交。
- 建立 append-only 审计日志和敏感字段访问记录。

验收：六个预置角色的允许/拒绝用例均有自动化测试；停用员工不能继续使用旧会话。

### 里程碑 2：客户与导入

- 客户主档案、来源、标签、负责人、阶段、备注和跟进任务。
- Excel/CSV 字段映射、预览、校验、批量导入、去重和失败明细。
- 客户合并、分配、转交、筛选和受控导出。

验收：使用脱敏样例完成重复手机号、微信号、空值、错误格式和跨批次重复导入测试；重复执行同一批次不产生脏数据。

### 里程碑 3：客服工作台与知识库

- 会话列表、客户上下文、AI 建议、人工接管和回复状态。
- FastGPT 连接器、超时、熔断、重试和降级。
- 知识资料的草稿、审核、生效、过期和版本记录。
- 风险规则、置信度阈值、引用记录和自动化暂停开关。

验收：普通 FAQ 可生成带引用回答；所有强制人工场景均无法自动发送；关闭 AI 后人工会话仍正常。

### 里程碑 4：报名、订单与财务台账

- 学历评估、院校专业方案、报名档案和材料清单。
- 订单、优惠审批、分期计划、收款确认、冲正和退款审批。
- 客户成交后一键建立学员服务档案，不复制客户主数据。

验收：金额计算、越权修改、重复回调、部分收款、逾期、退款和冲正均有测试；任何已确认资金记录都不能被覆盖。

### 里程碑 5：报表与上线演练

- 招生漏斗、成交额、实收、待收、逾期、退款和净回款。
- 按时间、人员、团队、校区、来源和产品筛选。
- 权限化 Excel 导出并记录导出审计。
- 脱敏历史数据导入、备份恢复、故障降级和安全验收。

验收：报表结果可逐笔追溯到订单和已确认资金记录；备份恢复演练成功；关键流程 E2E 测试通过。

## 6. 首批自动化测试清单

1. 相同手机号跨格式导入仍识别为同一客户。
2. 同昵称但不同手机号/微信号不得自动合并。
3. 客服不能读取其他团队客户，主管不能越过所属组织。
4. 财务可以确认收款但默认不能读取完整聊天内容。
5. 成交价、应收、实收、待收、退款和净回款计算一致。
6. 重复的支付或导入幂等键不会产生重复记录。
7. 已确认收款不能更新或删除，只能冲正。
8. 过期知识条目不会进入 AI 引用。
9. 投诉、退款、保过/包毕业、非标准优惠等消息强制人工。
10. FastGPT 超时后生成明确待办，会话消息不丢失。
11. 停用员工的旧会话立即失效，待办和客户成功转交。
12. 导出敏感字段需要独立权限，并产生审计记录。

## 7. 明天需要业务方补充的资料

这些资料不阻塞工程骨架，但会阻塞真实业务验收：

- 现有客户/学员 Excel 的脱敏样表和字段说明。
- 当前实际岗位、团队/校区结构以及一名员工是否兼任多个角色。
- 标准收费表、优惠审批规则、分期与退款规则。
- 报名材料清单及学员服务阶段。
- 第一批知识库资料、标准话术、禁答词和投诉/退费升级流程。
- 企业微信主体与可用接口情况；个人微信自动化在未验证前继续保持人工兜底。

## 8. 完成定义

第一阶段不是“页面都能点”就算完成，必须同时满足：

- 客户、报名、订单、收款、退款和报表的数据链路可追溯。
- 权限拒绝逻辑有测试，不依赖前端隐藏按钮。
- AI 回答有知识引用，风险消息能够稳定转人工。
- 所有生产密钥来自服务端密钥管理，浏览器和 Git 仓库中不存在真实密钥。
- 可以从备份恢复，并完成一次脱敏数据迁移演练。
- 管理者可用报表追溯到业务明细，金额无手工拼凑。
